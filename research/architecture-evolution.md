# Qualcomm 计算架构演进：从移动 SoC 到异构端侧平台

## 1. 演进主线不是“核心数越来越多”

Qualcomm 的计算架构可以沿四条相互咬合的线理解。第一条是 CPU 从早期自定义 Scorpion、Krait，到以 Arm 公版核心组合为基础的 Kryo，再到完全自定义 Oryon；第二条是 Adreno 从承担移动图形，扩展到通用计算、光线追踪、PC 级 API 和显示管线；第三条是 Hexagon 从低功耗信号处理器发展为含标量、向量、张量和专用数据通路的 NPU；第四条是 Spectra ISP、Sensing Hub、基带和 FastConnect 将摄像头、传感器与无线输入持续送入计算域。每代真正改变体验的往往不是单个峰值，而是这四条线能否少搬数据、少唤醒大核并由软件正确调度。[Q037][Q041][Q044]

Snapdragon 的“系统级”含义由此而来。相机按下快门时，传感器数据先经 ISP 做去马赛克、曝光融合、降噪与色彩处理，语义分割可能调用 Hexagon，CPU 处理控制和应用逻辑，GPU 承担预览合成，存储控制器写入编码结果；上传时又进入安全、调制解调与射频链。只看 CPU 分数会错过数据移动和协处理器占据的大部分能耗。反过来，模块齐全也不保证体验：驱动、模型分区、内存规划和 OEM 热设计若失配，专用单元可能闲置，任务仍回落到 CPU。

## 2. Scorpion 与 Krait：为移动功耗建立自定义 CPU 传统

早期 Snapdragon 以 Scorpion 和后来的 Krait 展示了 Qualcomm 不满足于把手机做成缩小版桌面系统。移动处理器需要极低待机、快速唤醒、集成基带和多媒体，并在几瓦甚至更低的短时预算内响应触控。Scorpion 是兼容 Arm 指令集的 Qualcomm 自定义实现；Krait 随 Snapdragon S4 和后续 800 系走向多核、高频与更先进制程。这个阶段奠定的不是某个今天仍可比较的 IPC 数字，而是“围绕终端工作负载共同设计 CPU、GPU、DSP、内存和调制解调器”的产品方法。

Snapdragon 800/805 到 820 是重要转折。产品命名由 S 系过渡到数字层级；Adreno 和多媒体能力逐渐成为旗舰差异点；820 使用新的 Kryo 品牌 CPU。旧产品官方页面仍保留在 8 系目录，说明系列历史连续，但页面在线不能被理解为仍处于主流供货期。[Q019] 对历史平台最可靠的研究方式是确认它在产品谱系中的角色，避免用十年后的软件或跑分去做不公平复测。

## 3. Kryo 阶段：从自定义核心到 Arm 核心组合

“Kryo”并不始终指同一种微架构。早期 Kryo 代表 Qualcomm 自定义 CPU，后来许多 Kryo 代际以 Arm Cortex 核心为基础，由 Qualcomm 做频率、缓存、互连、电源管理和系统级定制。把所有 Kryo 当成同一核心家族，会误判架构来源和性能变化。对于没有公开微架构白皮书的产品，本报告只使用产品页公布的核心角色与频率，不推测重命名关系。

现代手机 SoC 通常把 CPU 分成少量高性能核心、若干中间核心与效率核心。调度器根据负载、温度、前台状态和能耗模型选择核心；短任务可以迅速冲高频，长任务则受散热与电池电流限制。Kryo 时代的 8 Gen 1、8 Gen 2 和 8 Gen 3 体现了这种组合不断调整，同时把 AI、相机、游戏和连接作为整个平台卖点。[Q025][Q024][Q023] 因此“核心数相同”既不表示相同核心，也不表示相同缓存、内存或持续功耗。

8 Gen 2 的意义在于异构 AI 更深入进入影像、音频、调制解调与游戏；8 Gen 3 又把终端生成式 AI作为公开叙事重点。这里的“生成式 AI 支持”不是一个硬件开关，而是算子、精度、模型压缩、内存容量、运行时与应用共同结果。一个语言模型能启动，不等于首词延迟、每秒 token、功耗和上下文长度都适合产品化。

## 4. Oryon：重新进入完全自定义 CPU

Oryon 把 Qualcomm 的自定义 CPU 路线带回高性能通用计算。第一代先用于 Snapdragon X Elite/X Plus PC，随后进入 Snapdragon 8 Elite 手机；这次迁移说明 Qualcomm 试图用同一 CPU 技术覆盖从无风扇或轻薄 PC 到手机的不同功耗包络。[Q008][Q009][Q022] 但“同品牌 CPU”不等于物理实现完全相同：核心数量、缓存、频率、内存接口、功率管理和封装都会为目标市场调整。

第一代 Snapdragon X Elite 以多核 Oryon、Adreno GPU、Hexagon NPU 和常连接能力形成 PC 平台。与 8cx 相比，战略变化不是简单更新，而是尝试在原生 Arm64 Windows、x64/x86 仿真和 NPU 加速共同成熟时跨过应用兼容门槛。X Elite 与 X Plus 又通过核心、频率、GPU 等形成层级；OEM 最终可以用相同品牌做不同尺寸和散热的设备。[Q008][Q009][Q018]

Snapdragon 8 Elite 是 Oryon 向手机功耗域的第一次公开落地。它同时改变了 CPU 品牌、旗舰命名和平台定位，不能把“Elite”理解为 8 Gen 4 的纯营销别名。官方页把 Oryon、Adreno、Hexagon、X80 与 FastConnect 组合描述，说明移动实现仍依赖全 SoC 能效，而不只依赖 CPU。[Q022]

2025 年发布的 X2 Elite/Extreme 和 8 Elite Gen 5 都标注第三代 Oryon；X2 发布稿给出 80 TOPS NPU与 2026 上半年设备预期，8 Elite Gen 5 页面给出最高 4.74 GHz 和相对前代的官方性能/能效提升。[Q005][Q020] 同为“第三代”也不应推断核心完全相同，因为 PC 和手机在核心数、缓存、内存位宽、持续功耗与 IO 上差别显著。

X2 产品简报按零件号给出多组核心与内存配置，平台页还扩展出 X2 Plus。[Q006][Q007] 这意味着第二代 X 系列已从一个发布 SKU 变成层级体系。判断设备时必须记录零件号而非只写“X2”，并把发布稿中的预计可用时间与 2026 OEM 实际目录分开。[Q018]

## 5. Adreno：图形核心也是内存与软件问题

Adreno 的首要任务是把图形命令转为屏幕像素，但其系统影响远超游戏。Android 合成、相机预览、浏览器、机器学习计算、XR 畸变校正和 PC DirectX 都可能使用 GPU。移动 GPU 常采用适合带宽受限环境的渲染策略，尽量让中间数据停留在片上；若场景、驱动或 API 让数据频繁写回 LPDDR，理论算力并不能阻止能耗和延迟上升。

Qualcomm 不像桌面独显厂商那样对每代公开完整执行单元数量，因此用未授权数据库中的“着色器数”跨代排名风险很大。更稳妥的比较是：目标 API 是否支持、驱动是否由 OEM 持续更新、同一分辨率和画质下帧时间是否稳定、GPU 活跃度与内存带宽是否饱和。Snapdragon Profiler 可观测 CPU/GPU/DSP 指标，是定位瓶颈的工具，而不是自动给出优化答案。[Q047]

8 Gen 2 开始的硬件加速光线追踪、8 Gen 3 与 Elite 世代持续增强的 Elite Gaming 功能，使手机渲染更接近桌面 API 概念。[Q024][Q023][Q063] 但移动光追受功耗、带宽和内容生态制约；一个演示支持光追不等于大型游戏在原生分辨率下长期维持相同质量。开发者通常需要动态分辨率、可变率着色、上采样和资源压缩共同配合。

PC Adreno 面对另一项挑战：DirectX 功能和驱动兼容。原生 Arm64 游戏、x64 仿真游戏、反作弊驱动和图形中间件的可运行性不同。CPU 仿真能够翻译用户态指令，却不能替代缺失的 Arm64 内核驱动；图形 API 可映射也不保证着色器编译和反作弊兼容。评价 X 系列游戏能力必须逐个应用验证，不能用 GPU 峰值代替兼容矩阵。

## 6. Hexagon：从 DSP 到可编程 NPU

Hexagon 的历史优势是以低功耗处理音频、传感和通信信号。随着 HVX 向量扩展、张量加速器和标量控制的组合，Qualcomm AI Engine 把 CPU、GPU 与 Hexagon 纳入异构推理。NPU 适合结构规则、可量化且受运行时支持的算子；CPU 适合控制密集和长尾算子；GPU 适合并行且已有图形/计算数据的工作。最佳分区要减少跨处理器同步和格式转换，而不是把尽可能多的节点强塞进 NPU。

QNN/AI Engine Direct 为开发者提供后端、图编译、量化与执行接口；Hexagon NPU SDK 面向更底层能力；SNPE 是成熟的模型部署工具；QAIRT 则逐步统一当前分发与运行时入口。[Q041][Q042][Q043][Q044] 名称并存反映生态迁移，项目必须按 SDK 版本、目标 SoC、操作系统和模型算子确认支持，不能把文档中某一工具的能力自动复制给其他工具。

TOPS 是最容易误用的规格。它通常以低精度整数乘加计数，但是否按一次乘和一次加计为两个操作、是否允许稀疏、峰值能否由真实图持续利用，都影响含义。X2 的 80 TOPS 是官方 NPU 平台口径；应用吞吐还受内存、模型形状、编译器、批量大小与热预算影响。[Q005] 对交互式端侧 AI，首 token、每 token 延迟、唤醒开销和内存峰值往往比峰值 TOPS 更重要。

Sensing Hub 上的微型计算单元承担始终感知场景：音频唤醒、低功耗传感融合或情境检测不必持续唤醒大 CPU/NPU。它的价值是降低平均能耗和响应延迟，不是替代高吞吐 Hexagon。8 Elite Gen 5 页面把个性化知识、传感与 NPU结合，是“分层 AI”设计的公开实例。[Q020]

## 7. Spectra ISP：从成像流水线到传感器—AI闭环

Spectra ISP 接收 Bayer/RAW 数据，执行曝光、降噪、色彩、镜头与几何校正，再把结果交给编码、显示或 AI。多 ISP 允许并行处理多摄像头或更高像素率，但最终质量仍取决于传感器面积、镜头、标定、OEM 算法和曝光策略。官方相机页面强调计算摄影和 AI 协同，不能据此得出使用同一平台的手机成像相同。[Q037]

8 Elite Gen 5 的三路 20-bit ISP 是当前旗舰的重要变化；20-bit 描述内部处理深度和动态范围能力，不意味着文件一定以 20-bit 保存，也不意味着显示屏能呈现全部范围。[Q020] 相机数据常是 SoC 中最大的持续流量之一，ISP 与 Hexagon 之间的直连、片上缓存和压缩能减少 LPDDR 往返。若算法要求把每帧复制到 CPU 用户空间，再送 NPU，性能与功耗会迅速恶化。

视频还有更复杂的稳态约束。高分辨率高帧率录制同时占用传感器、ISP、NPU、视频编解码、内存、存储和无线，机身温度上升后任何环节都可能降级。评测应记录持续录制时间、是否丢帧、亮度或功能是否被限制、文件码率与电池下降，而不是只记录菜单中存在某个模式。

## 8. Modem-RF 与 FastConnect：连接不是一个峰值速率

Qualcomm 把“modem-RF system”作为整体，是因为数字基带、收发器、射频前端、天线调谐、包络跟踪和算法共同决定覆盖、吞吐与能耗。X85 页和 8 Elite Gen 5 页给出的 12.5 Gbps 下行、3.7 Gbps 上行等是满足运营商频谱、载波聚合、网络配置与信号条件后的理论峰值。[Q038][Q020] 日常用户速度通常由网络拥塞、频段、天线姿态和套餐限制决定。

独立基带和集成基带各有权衡。集成可减少板级芯片和接口功耗；独立方案允许计算平台与蜂窝产品周期解耦，并面向 PC、汽车或固定无线选择不同配置。平台支持某个基带不代表所有 OEM 设备都装配它，尤其是 PC 常把 5G 作为选配。

FastConnect 把 Wi-Fi、蓝牙，有时还包括 UWB 的协调放在同一连接系统。FastConnect 7900 支持 Wi-Fi 7、多链路和蓝牙/UWB 协同，但终端需要合适天线、射频设计、地区法规和驱动才能兑现。[Q039] Snapdragon Connect 是更高层的端到端认证品牌，试图把峰值规格转成覆盖、响应与续航要求；认证仍不能替代对具体网络环境的测量。[Q040]

连接与计算越来越直接耦合。云游戏的帧时间包含 GPU 渲染、编码、Wi-Fi 排队、空口、路由和服务器；无线耳机延迟包含应用缓冲、音频 DSP、编解码、蓝牙调度与耳机端处理；XR 分体式计算还要保证姿态和图像的时序。只优化其中一个组件会遇到 Amdahl 定律，端到端跟踪必须使用共同时间戳。

## 9. 安全、虚拟化与电源管理是隐形架构

现代 Snapdragon 平台必须隔离安全启动、密钥、支付、生物识别、基带、DRM 与普通应用。公开产品营销通常用“安全处理单元”“可信执行环境”等名称，但具体认证和威胁模型因平台与终端而异。安全域会影响内存共享：摄像头受保护内容、DRM 视频或车载安全关键数据不能任意映射给所有加速器。

PC 与汽车增加了虚拟化复杂度。Windows 的系统管理、企业安全和虚拟机需要固件与驱动共同支持；Digital Chassis 的座舱可把多个显示/操作系统隔离，Ride Flex 又要处理混合关键性工作负载。[Q073][Q074][Q075] “同一 SoC 运行多个域”减少盒子与线束，但也扩大资源仲裁、故障隔离和安全验证责任。

电源管理贯穿全部模块。DVFS 根据负载和温度改变电压频率，电源岛关闭闲置单元，调度器选择 CPU 核心，NPU/DSP 让大核更早休眠。实际能效是完成用户任务的总能量，包括唤醒、数据复制、等待无线和屏幕；单个加速器的每瓦算力只是局部指标。

## 10. 从演进中得到的工程结论

第一，自定义 CPU 回归使 Qualcomm 能更主动地在 PC 与手机之间复用设计，但跨功耗域仍需要不同物理实现与系统权衡。第二，Adreno、Hexagon、Spectra 和连接系统的协同是平台护城河，软件是否能减少内存往返决定了协同能否兑现。第三，产品层级越来越复杂，系列名不足以确定核心、频率、NPU、内存和蜂窝配置，零件号与 OEM SKU 才是验证单位。

第四，Qualcomm 的路线从手机外溢到 PC、眼镜、网络、汽车和数据中心，不代表一套软件二进制可以无缝横跨所有市场。共同的 AI 与连接概念有助于复用模型和工具，但操作系统、功能安全、驱动发布、生命周期和开发权限仍然分裂。第五，任何“代际领先”都需要放回相同任务、功耗、软件和终端设计中验证；架构分析的价值是解释为什么结果可能出现，而不是替结果预先下注。
