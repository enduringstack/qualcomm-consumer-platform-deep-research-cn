# 内存与端到端协同：CPU、GPU、NPU、ISP、DSP、PCIe、USB 和无线

## 1. 共享内存不是“零成本统一内存”

多数 Snapdragon/Qualcomm 端侧平台由 CPU、Adreno GPU、Hexagon NPU/DSP、Spectra ISP、视频编解码、显示、Sensing Hub、基带和安全单元共享一组外部 LPDDR。共享物理内存的价值是避免每个加速器配置独立显存，也允许缓冲区在多个模块之间传递；它并不保证完全零拷贝、统一虚拟地址、缓存自动一致或任意模块都能访问同一安全域。

一份相机帧可能有传感器 RAW、ISP 中间面、YUV/RGB、NPU 张量、GPU 纹理和编码输出。格式、行跨度、压缩、对齐和保护属性不同，即使底层物理页相同，也可能需要转换或重新分配。真正的零拷贝是“同一缓冲由生产者写、消费者直接读且同步正确”，不是 API 名称中出现 shared memory。

共享 LPDDR 也意味着竞争。CPU 缓存未命中的请求、GPU 纹理、NPU 权重、ISP 连续帧、显示扫描、视频编码和基带 DMA 同时占用内存控制器。厂商公布的理论带宽是传输率乘总线宽度的上限，实际要扣除协议、刷新、仲裁、读写转向和访问局部性。X2 不同 SKU 的 128/192 位内存配置会直接影响图形与 AI 余量，但 OEM 容量和颗粒又决定具体设备。[Q006]

## 2. CPU 缓存与一致性

Oryon 或 Kryo CPU 内部有多级私有/共享缓存，公开产品页通常只给总缓存或不披露分级。总缓存不能简单除以核心数，也不能推测每级延迟。程序性能取决于工作集、访问模式、预取和核间迁移；调度器把线程移动到另一个核心簇可能失去热缓存，却换来更好的能耗或温度。

CPU 与设备之间的一致性有硬件一致、软件维护和不可缓存映射等方式。驱动在把缓冲交给 GPU/NPU/ISP 前后可能执行 cache clean/invalidate 或同步 fence。漏同步会产生旧数据或撕裂，过度同步又会串行化流水线。Android 的 dma-buf、Linux 驱动与 Windows 图形/计算栈负责把这些细节封装，但高性能应用仍需理解所有权转换。

大语言模型在 CPU/NPU 上执行时，权重读通常是带宽密集，KV cache 随上下文增长。增加核心或 TOPS 不会增加 LPDDR 容量；当工作集超过内存，移动系统没有独显那样的备用显存，交换到 UFS/NVMe 会带来数量级更高延迟。模型选择必须先做常驻集预算，再谈峰值算力。

## 3. GPU 内存行为

Adreno 采用适应移动功耗的片上缓存与渲染策略，目标是减少中间颜色、深度和模板数据写回 LPDDR。若游戏能在片上完成一块区域再提交，能耗和带宽都更低；过多 render pass、频繁读回、超大纹理和不合适的附件会破坏这种优势。

PC Adreno 面向 DirectX/Vulkan/OpenCL，内存管理还涉及 Windows 驱动模型、共享系统内存、分页与应用仿真。[Q008][Q016] “共享内存”不等于 GPU 可以占用全部系统 RAM：操作系统设置预算，超预算资源可能被驱逐和重新提交。应用读取 GPU 结果会触发同步，最坏情况下 CPU 等待整个命令队列。

移动游戏的分辨率是带宽乘数。像素数上升会增加颜色/深度、后处理和显示流量；高刷新率又按帧率放大。光线追踪增加结构访问和不规则内存请求，常需要动态分辨率、上采样和压缩配合。Elite Gaming 的功能只有在引擎和驱动正确使用时才减少瓶颈。[Q063]

GPU 性能诊断应看帧时间，而不是平均 FPS。CPU 提交慢表现为 GPU 空闲，着色/纹理瓶颈表现为 GPU 高占用，带宽瓶颈表现为频率提高但吞吐不再线性增长，热瓶颈表现为若干分钟后频率和功耗下降。Snapdragon Profiler 提供计数器，开发者需用阶段标记把指标映射回帧。[Q047]

## 4. NPU/DSP 的张量布局与量化

Hexagon NPU由标量控制、向量和张量单元组成，编译器把模型图映射为后端支持的算子。[Q042][Q044] 算子落在 NPU 不代表数据始终停留在 NPU 本地存储；权重和激活通常从共享内存分块搬入片上缓冲。卷积、矩阵乘和注意力的 tile 大小决定复用率，形状不适配会降低利用率。

量化不仅把 FP32 改成 INT8。需要校准范围、选择逐张量或逐通道尺度、处理异常值、验证精度，再由编译器插入量化/反量化。若图中大量算子只能在 CPU 执行，处理器间往返可能抵消 NPU 优势。Gen AI 扩展和 AI Hub 可以提供已优化工件或配方，但目标设备和运行时版本必须匹配。[Q045][Q046]

模型分区应以端到端延迟和能量为目标。一个小前处理算子留在 CPU，随后大段 NPU 执行，可能比为追求“百分之百 NPU”多次转换格式更快。音频和传感工作常适合 Hexagon DSP 或 Sensing Hub，因为吞吐不大却要求持续运行；大 NPU 短时启动的固定开销可能更高。

## 5. ISP、视频和显示路径

相机输入是规则的高带宽 DMA 流。传感器通过 MIPI CSI 进入 ISP，Spectra 生成若干输出面，NPU可做场景/对象/分割，视频编码器生成压缩流，显示控制器把预览扫描到屏幕。[Q037] 若每一步都通过 CPU 拷贝，带宽会近似按中间面数量累加；使用共享缓冲和硬件 fence 可把 CPU 降为编排角色。

图像格式决定成本。RAW 保留传感器信息但数据量大；YUV 适合视频与 ISP；RGB 适合显示和部分模型；NPU 可能要求 NHWC、特定量化和 padding。颜色空间转换看似简单，4K 多帧时会占显著带宽。管线设计应尽量让模型直接消费 ISP 可生成的格式。

视频解码后的帧可以直接交给显示合成，受保护内容还要求安全视频路径。屏幕录制、视频会议背景分割或滤镜会迫使帧进入额外处理域，增加一次或多次读写。HDR 又引入色调映射和高位深。用户看到的“视频播放功耗”包含显示面板、无线、解码、音频和系统后台。

## 6. LPDDR 容量、速率、位宽和封装

LPDDR 的传输率以 MT/s 表示，理论十进制带宽近似为传输率乘总线位宽再除以八。这个公式不包含控制器效率，也不能从带宽推断延迟。更高数据率可能需要更复杂信号完整性和功耗管理，轻负载时控制器会进入低功耗状态，唤醒也有延迟。

手机常把内存封装靠近 SoC 以缩短走线，PC 平台可以支持更大容量和更宽总线。X2 Extreme 的高配 SKU具有更宽内存接口，适合 GPU 与本地模型并发，但 OEM 是否提供 64/128 GB 是终端选择。[Q005][Q006] 规格表中的“最大容量”是控制器能力，不是产品承诺。

内存容量规划应保留系统余量。Android 后台、相机多帧、GPU纹理和模型可同时达到峰值；Windows 本地模型还与浏览器、IDE 和共享 GPU 争用。仅以模型文件大小估算会漏掉解压、量化元数据、激活、KV cache、编译器 workspace 和双缓冲。

## 7. 片上互连与服务质量

异构 SoC 需要片上网络连接计算、内存、IO 和安全域。公开营销常不给出拓扑，不能假设所有模块点到点直连。互连控制器会按优先级和带宽合同仲裁：显示扫描和相机输入不能因后台 AI 推理而断流，基带实时任务也有截止期。

服务质量的代价是某些低优先级任务吞吐波动。NPU 基准在空闲设备上达到稳定速度，不代表录制视频、5G 上传和高亮屏幕同时开启时仍相同。系统级测试应组合并发负载，记录用户关键路径与后台吞吐，而不是逐模块跑完再相加。

热管理也是一种互连资源管理。CPU、GPU、NPU和基带共享封装与机身散热，某个模块持续满载会减少其他模块功耗头寸。弱信号 5G 上传时射频热量可能让游戏更早降频；高亮 HDR 显示又提高表面温度。整机功耗预算不是每个峰值功耗之和。

## 8. PCIe：PC、IoT 与数据中心扩展

PCIe 用于 NVMe、独立控制器、网卡或数据中心加速卡。链路带宽由代际、lane 数、编码与协议开销决定；平台支持 PCIe 5.0 不表示每个设备都给 SSD 足够 lane，也不表示 SSD 能持续达到标称速度。X2 简报中的双 PCIe 5.0 是平台 IO 能力，OEM 可以选择端口与设备拓扑。[Q006]

NVMe 数据从 SSD 经 PCIe 到系统内存，再由 CPU/GPU/NPU消费。是否能绕开多余复制取决于驱动和应用；Windows DirectStorage 等机制也需要软件链配合。小文件随机读取受队列和延迟限制，大顺序读取更接近链路带宽，不能用一个磁盘分数代表模型加载。

IoT 平台通过 PCIe 连接相机桥、以太网、5G模块或加速器，工业设计还要验证复位、热插拔、ASPM、电磁兼容和错误恢复。省电状态可以降低待机，却增加唤醒延迟；实时系统可能选择不同策略。

数据中心 Cloud AI/Dragonfly 设备若以 PCIe 接入主机，端到端推理包含主机预处理、内存固定、DMA、设备执行和结果回传。[Q079][Q082] 大批量隐藏传输延迟，交互服务则更敏感。没有高效 batching 和调度，芯片峰值不能转化为服务器吞吐。

## 9. USB、显示与外设

USB 名称包含连接器、协议和可选功能。USB-C 只描述物理接口；USB 3.x、USB4、DisplayPort Alt Mode、供电和 Thunderbolt 兼容是不同层。Snapdragon PC 平台支持某能力，OEM 仍可能让左右端口带宽或显示能力不同。购买扩展坞应查具体机型手册。

USB 外设兼容不仅是总线问题。键盘和存储使用类驱动通常简单，打印、专业音频、采集卡、调试器和安全令牌可能依赖厂商 Arm64 驱动。x64 应用仿真不能加载 x64 内核驱动。[Q016] 企业部署应真实插接、睡眠唤醒、固件更新和高负载传输测试。

外接显示同时占用 DPU、内存和接口。高分辨率高刷新 HDR 可能消耗可观显示带宽，并影响 GPU 可用带宽。扩展坞若共用一条上行链路，显示、网卡和 SSD 会竞争。规格表中每个功能分别达到最大值，不表示可同时达到全部最大值。

## 10. 蜂窝、Wi-Fi、蓝牙与 UWB 的协同

无线数据进入 SoC 前已经经历射频、基带或 MAC 调度。蜂窝基带处理编码、调制、载波聚合与协议，CPU 承担高层网络栈，应用通过 socket 读写。理论 12.5 Gbps 下行需要 X85 支持之外的运营商频谱和网络条件。[Q038]

Wi-Fi 7 多链路可在多个频段调度，目标包括吞吐、时延和可靠性；FastConnect 7900 还把蓝牙与 UWB 协同纳入平台。[Q039] 实际收益受路由器、法规、天线和共存影响。同一 2.4 GHz 空间里 Wi-Fi 与蓝牙需要协调时隙，繁忙网络可能让音频重传。

UWB 提供精确测距/方向能力，但完整应用需要双方设备、天线标定、安全协议与操作系统 API。把 UWB集成进连接系统可降低器件与同步成本，不自动解决跨品牌互操作。位置隐私也需要用户授权和防跟踪设计。

无线与 NPU 协同越来越多：基带用 AI改善信道/天线策略，Wi-Fi用 AI分类流量，耳机用 AI降噪，端侧助手决定何时访问云。这里的“AI”可能是小型专用模型，不应与大语言模型的算力口径混为一谈。

## 11. 五条典型端到端数据路径

**拍照。** 传感器进入 Spectra，ISP 输出供 Hexagon 分割和 GPU 预览，CPU 协调多帧，编码器写入 UFS；瓶颈可能是曝光等待、内存、算法或存储。评测需把按快门到可预览、到可再次拍摄、到最终保存分别计时。

**视频会议。** 摄像头与麦克风经 ISP/DSP，NPU做背景/眼神/降噪，编码器压缩，Wi-Fi/5G发送；接收侧解码、GPU合成和扬声器播放。NPU加速节省 CPU 不一定减少网络抖动，整体体验由最慢环节决定。

**本地大模型。** 存储读取权重到 LPDDR，运行时编译/加载，NPU/GPU/CPU执行，token 返回 UI；容量、内存带宽、算子回退和温度共同影响。首轮还含模型加载，热缓存轮次不能代替冷启动。

**XR。** 摄像头/IMU进入 ISP 和视觉算法，姿态预测驱动 GPU 渲染，合成器畸变校正后显示；无线分体又加入编码和空口。P99 帧时间和追踪稳定比平均吞吐重要。

**云 AI。** 手机/PC 本地预处理和隐私过滤，经无线与互联网到数据中心，主机把请求提交给 Dragonfly/Cloud AI，加速器生成后返回；成本由端侧能耗、网络、服务端利用率和模型质量共同决定。[Q083]

## 12. 性能排查次序

先确认任务是否在目标处理器执行，而不是凭宣传猜测。再画出生产者、缓冲格式、消费者和同步点，统计每步数据量。随后查看 CPU/GPU/NPU活跃时间、内存带宽、缺页、温度和频率。只在证据显示某环节饱和后调整模型、分辨率、批量或线程。

如果 GPU 慢，先排查 CPU 提交、分辨率、纹理和带宽；如果 NPU慢，排查回退算子、量化、形状和跨域复制；如果相机卡顿，排查传感曝光、ISP、算法与存储；如果网络慢，分离局域网、空口、运营商和服务器；如果整机几分钟后变慢，记录温度与功率而不是继续换一个短跑分。

端到端协同的最终原则是：数据移动通常比一次算术更昂贵，共享资源必须在并发下验证，平台上限不是终端保证，专用加速器只有被软件稳定调用才有价值。Qualcomm 的优势正是模块丰富；工程风险也正是模块、驱动和责任边界足够多。
